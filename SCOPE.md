# SCOPE — MusicBrainz-automated

*Version 0.1 — 2026-09-02 — draft for review*

## 1. Purpose

Build a tool that automatically tags and reorganizes a large personal music library
(~1000+ albums) against **MusicBrainz**, with **Discogs** as fallback, and brings every
file into the folder layout, naming, and metadata format defined in `config.yaml` —
a clean, consistent base for a later Plexamp setup.

**The project ends at a correctly tagged, correctly laid-out library.**

## 2. Out of scope

- **Everything Plexamp**: install, configuration, library scanning, sonic analysis, uploads, Plexamp-side playlists. Not this project.
- Acquiring music: ripping, downloading, converting.
- Audio transcoding/re-encoding, ReplayGain/loudness processing.
- Splitting cue sheets or one-file recordings into individual tracks.
- Contributing corrections back to MusicBrainz/Discogs.
- A GUI — this is a CLI tool.
- Deezer integration (stays commented out in config unless enabled later).
- General file management of non-audio files (.nfo, logs, images ≠ cover) beyond ignoring them.

## 3. Binding decisions from config.yaml

- Per-machine paths (library root, trash dir, token file) are generated by the
  `musik setup` wizard into a local `config.yaml` — no machine-specific config
  is committed to the repository.
- Import **moves** files (no copy) and **writes tags** into the files.
- Layout templates:
  - Albums: `$albumartist\$original_year - $album%aunique{}\%if{$multidisc,$disc-}$track $title`
  - Singles: `Singles\$artist\$year - $title`
  - Compilations: `Compilations\$original_year - $album\%if{$multidisc,$disc-}$track $title`
- Genres: lastgenre (album-level, 3 genres, canonical, specific preferred) with Discogs style appended.
- Art: `cover.*`, sources filesystem → coverart → itunes → amazon → albumart.
- Discogs credentials are sourced from a local `discogs_token.json` — never hardcoded or committed.
- `musik.trash_dir`: displaced files go to `<library>\_trash\<reason>\` with a `manifest.csv` for audit and restore. Nothing is ever deleted outright.

## 4. In scope

### 4.1 Deliverable & environment

- A Python CLI tool (working name **`musik`**, per the config's `musik:` section) living in this project dir. It orchestrates beets non-interactively: pre-scan, import, review-queue handling, retries, reports. Sketch of commands: `scan`, `import [--dry-run]`, `apply` (review decisions), `retry` (unmatched), `asis` (explicit as-is filing of tag-complete units), `report`, `dedupe`.
- Environment setup is automated by the Windows installer (`install.bat`):
  Python 3.10+, a venv, beets 2.13+ and its plugins (musicbrainz, discogs,
  lastgenre, chroma, fromfilename, duplicates, fetchart, inline), the
  chromaprint `fpcalc` binary, and the per-machine `config.yaml` via the
  setup wizard.
- A first-run safety gate: the first pass over the real library is preceded by a dry-run report (classification + match preview, no files touched) and a backup/snapshot recommendation.

### 4.2 Input material the tool must handle

| Material | Handling |
|---|---|
| Albums, EPs, singles, best-ofs | Normal grouped import |
| Multi-disc albums | Per-config `disc-` prefix layout |
| Various-artist compilations | `Compilations\` template, `va` detection |
| "Top N" containers: one folder holding ~100 different artists' albums | Pre-scan splits it into per-album import units — never imported as one giant release |
| Vinyl rips (track-per-side, A/B in titles, long tracks) | Tolerant matching; MB/Discogs side-based releases |
| One-file live recordings (single long file) | Tagged as best-guess singleton; no cue splitting |
| Playlists (m3u/m3u8, assorted-track folders) | Read entries; each referenced audio file imported as a singleton under `Singles\`; the playlist file itself is untouched |
| Non-audio files | Ignored, left in place, noted in the report |

### 4.3 Identification & auto-accept policy (forgiving, not blind)

- Primary source: MusicBrainz via beets, metadata plus **chroma acoustic fingerprinting**.
- Fallback: Discogs (token from `discogs_token.json`).
- **Priority chain**, first tier that accepts wins:
  1. *MB strict* — names and durations agree directly;
  2. *MB enhanced* — the same release behind minor noise: small spelling deviations, credit-formatting differences (`5MIINUST` vs `5MIINUST, nublu`), reissue/remaster years, subtitle variants, 1–3 track-count deviations (unmapped local files archived to `_trash\unmapped-track\` with a manifest), duration drift up to 10 s, vinyl side numbering;
  3. *own metadata* — only when the sources genuinely don't know the release (no candidates, or best candidate unrelated beyond distance 0.35; never after a network failure), the tags are complete and consistent, and the folder-name parse agrees with the tags. Units import on their own tags, status `asis`, re-taggable when MusicBrainz catches up;
  4. *review* — contradictory tags/folder, middle-band candidates (0.25–0.35), untagged files.
- A folder-name year only vetoes a candidate that looks like a *different recording* (live/broadcast/demo-style tokens) or drops part of the album title.
- **Not blind**: rate-limited or failed lookups never count as "no match"; wrong-artist/wrong-album candidates in the ambiguous band go to review.

### 4.4 Rate limiting & reliability rules

- Respect MusicBrainz (1 req/s), Discogs authenticated limits, AcoustID, and last.fm quotas: throttle, back off, retry on 429/timeouts.
- Distinguish **"no match found"** from **"request failed"**.
- A rate-limited or failed lookup **never** results in an as-is import. Affected items are queued for retry within the same run.
- Long runs are resumable (progress state + beets import log); a crash does not restart from zero. Batching is sized to survive network errors.

### 4.5 Review flow (CSV + apply, interactive review, explicit as-is)

- Everything below auto-accept confidence lands in a generated `review.csv` (best-guess candidates, scores, reasons) — no interactive popups during the run.
- The user edits the CSV at their leisure; a follow-up command applies the decisions in batch (accept candidate / apply override / leave unmatched).
- **`musik review` (interactive, on demand)**: after a run, walk the queue per unit with beets-style choices — accept candidate 1/2/3, override search, apply a MusicBrainz/Discogs ID directly, import as-is, skip, ignore forever, abort the rest.
- **`musik asis` (explicit opt-in)**: for review/unmatched units whose files already carry complete, consistent artist/album/title tags (typical for scene rips), this command files them using their own tags — never automatic, always user-invoked. Duplicates still resolve by quality, art and genres are still fetched, units are marked `asis` in the state.
- **Drag & drop entry** (`import-here.bat`): scan → import → interactive review → report for any folder dropped onto it.

### 4.6 Unmatched files

- Audio files that cannot be confidently identified after all attempts **stay in place, untouched**, and are recorded in `unidentified.csv` with reasons — ready for a later `retry` pass (e.g. after metadata improves or files are renamed).

### 4.7 Duplicates & displaced files

- Detect duplicates; keep the better-quality copy; move the loser to `_trash\<reason>\` (e.g. `better-bitrate`) with a `manifest.csv` entry, per the `musik:` config section.

### 4.8 Reporting & source-folder lifecycle

- Import report with counts and per-item logs: identified/auto-accepted / review-queued / unmatched / non-audio. Every imported unit carries a **track-by-track protocol** (`direct` MusicBrainz match vs `enhanced`-acceptance vs `unmapped` archived) and an album summary line.
- **`musik cleanup`**: after import, packaging junk (.nfo/.sfv/.m3u/…) of albums whose audio has moved is archived to `_trash\source-cleanup\`; emptied folders are removed; a dropped source root is deleted only once nothing at all remains inside it. Folders whose units still wait in review keep their audio and are never touched.
- Final verification pass: tree matches the config.yaml templates, cover art and genres present, every item from `unsorted` accounted for.

## 5. Acceptance criteria

1. After a run, every audio file is in exactly one state — tagged+moved, review-queued, or unmatched-listed. No silent skips.
2. Confident matches (e.g. a 1 s duration drift on one track) import with **zero interaction**.
3. Deliberately wrong album/track names are caught and queued for review, not accepted.
4. Rate limiting never causes untagged files to be accepted as-is; interrupted runs resume without redoing finished work.
5. The resulting tree matches the config.yaml path templates; cover art and ≤3 canonical genres present.
6. Duplicate losers sit in `_trash` with a manifest; nothing is deleted.

## 6. Target material

The owner's library mixes a large "1001 Albums You Must Hear Before You Die"
multi-artist container, 0-day scene WEB releases (brand-new, often absent from
MusicBrainz/Discogs), radio DJ mixes, and assorted album rips — the stress
test for §4.2. The tool must work for any mix of material, not just these.

## 7. Setup & environment

- `musik setup` generates `config.yaml` per machine (library root, Discogs
  token, tuned match/import settings) — personal config and tokens stay local.
- The Windows installer (`install.bat` → `install.ps1`) provisions Python, a
  venv, dependencies, and the chromaprint `fpcalc` binary.
- fetchart min/max-width constraints require ImageMagick and are therefore
  omitted from the generated config.
